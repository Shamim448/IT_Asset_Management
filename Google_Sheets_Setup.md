# Google Sheets + Apps Script Setup (Step-by-Step)

## 1. Create the database
1. Open Google Drive.
2. Create a new Google Sheet.
3. Give it a name such as **IT Asset Management DB**.
4. Copy the Spreadsheet ID from the URL:
   `https://docs.google.com/spreadsheets/d/1-Zz3djh66N78o26uqaEBCpLpQFW3-SDQrqg1huHJyC4/edit`


## 2. Create the Apps Script backend
1. In the Sheet, choose **Extensions → Apps Script**.
2. Delete the default code.
3. Open the supplied `Code.gs`.
4. Paste the complete code.
5. Replace:
   `PASTE_GOOGLE_SHEET_ID_HERE`
   with your Spreadsheet ID.

## 3. Run setup
1. In Apps Script, select function **setup**.
2. Click **Run**.
3. Approve the requested Google permissions.
4. The following sheets are created automatically:
   - Assets
   - Repairs
   - Users
   - Departments
   - AssetTypes
   - Brands
   - IDRegistry
   - Sessions
   - AuditLog

## 4. Demo login
After setup:
- Email: `admin@example.com`
- Password: `admin123`

**Immediately create/change your real Admin account and stop using the demo account.**

## 5. Deploy the API
1. Click **Deploy → New deployment**.
2. Select **Web app**.
3. Execute as: **Me**.
4. Who has access: choose the narrowest option that covers your intended users.
5. Deploy.
6. Copy the Web App URL ending in `/exec`.

## 6. Connect the frontend
Open:
`js/app.js`

Change:
`const API_URL = "";`

to:
`const API_URL = "YOUR_WEB_APP_EXEC_URL";`

Example:
`const API_URL = "https://script.google.com/macros/s/XXXXXXXX/exec";`

Do not use the `/dev` URL for production.

## 7. Host the frontend
You can host the folder on:
- your internal web server
- GitHub Pages
- Netlify
- Vercel
- another HTTPS static host

Open `index.html`.

## 8. If the browser blocks API requests
Some hosting/security combinations can restrict cross-origin requests to Apps Script. If that happens, the most reliable alternative is to serve the UI from the same Apps Script project (while keeping source modules separated conceptually). Do not weaken browser security just to make the API work.

## 9. User roles
### Admin
- Full access
- Asset add/edit/delete
- Status
- Repair add/edit/delete
- Completed repair edit
- Import
- Restore
- User management
- Master data
- Audit

### Normal User
- Dashboard
- Asset list
- Add asset
- Change status
- View repair history
- Add repair
- Export
- Backup

Server-side authorization is enforced in `Code.gs`; hiding a button is not the security boundary.

## 10. Asset ID rule
Asset IDs are generated by the server.
Format:
`IT-0001`, `IT-0002`, ...

Deleted IDs remain in `IDRegistry`, so they cannot be reused.

Excel import:
- Existing/registered ID → skipped
- Missing ID → generated automatically
- A duplicate ID list is returned after import

## 11. Repair rules
- Moving an asset to **Under Repair** automatically creates a repair record.
- Auto repair date = today.
- Auto status = In Progress.
- Only **Completed** repairs are included in completed repair cost and last-completed-repair analytics.
- Completed/Returned requires Return Date.
- Completion changes Asset Status to Active.

## 12. 120-day analytics
The dashboard calculates the 120-day threshold from the current system date.
Only Laptop and Desktop assets with at least one Completed repair are included.
Assets with no repair history are excluded.

## 13. Warranty
- Expired: latest 10, most recently expired first.
- Expiring Soon: today through next 60 days.

## 14. Backup / Restore
- Normal User: backup/download only.
- Admin: backup + restore.
- Always test restore on a copy before using it on the live database.
